# Native image metadata

The GraalVM image builder needs to be told about anything reached reflectively, since it cannot see
such uses by static analysis. Quarkdown declares that in three ways, none of which involve recording
a program run.

## Derived from the dependency jars

Reflection over third-party classes is generated by `generateNativeImageReflectionMetadata`, defined
in `quarkdown-cli/build.gradle.kts`. Rather than listing classes, it declares *scopes*: which library
reflects over which package, and why. The classes are then enumerated from the jars on every build.

Currently four scopes: LSP4J's protocol types (Gson reads their fields), JNA and the macOS file
watcher behind `--watch`, and flexmark's enums.

Registering a whole package is coarser than any single run needs. That is the point: the cost is a
slightly larger binary, and the benefit is that no future code path can reach a class the build forgot
to declare. Because the list is recomputed from the jars, a dependency upgrade is picked up on its own,
and a renamed or removed dependency fails the build instead of quietly registering nothing.

The result is also platform-independent: a jar's contents do not depend on the machine reading it.

## Declared by hand

`jni-config.json`, `proxy-config.json` and each module's `resource-config.json` are written by hand and
must stay that way, because none of them is derivable.

`jni-config.json` is JNA's callback contract: its native library calls *back* into Java, and the types
it constructs and reads on the way have to be reachable from native code. Reflection registration is
not enough, and the list cannot come from scanning a jar, because half of it is JDK types (the boxed
primitives, the NIO buffers, `String`, `Class`). Get this wrong and `--watch` does not throw: it
segfaults the moment the macOS watcher starts. The set is JNA's published ABI, so it changes only when
JNA's own native code does.

A dynamic proxy is a structural requirement of a feature: `--watch` cannot work on macOS without JNA's
proxy, and the language server cannot start without LSP4J's. There are two of them, and they change
only when the feature does.

Resources are declared by *pattern* because which one is needed depends on user input at run time:
`.doclang` picks a locale, `.bibliography style:` picks a CSL style. No enumeration of a particular
run could cover them, so the patterns cover the families instead. The
`verifyNativeImageResourceCoverage` Gradle task fails the build if a shipped resource matches none of
them, which is what stops a newly added resource from going missing.

## Left to the libraries

log4j, Netty, Ktor and Mordant ship their own reachability metadata inside their jars, and the GraalVM
reachability metadata repository (enabled in `graalvmNative`) supplies more. Quarkdown declares none of
it: duplicating that here would mean maintaining a stale copy of somebody else's file.

## Quarkdown's own code

Nothing to declare. Native functions are invoked through generated code rather than reflection, so the
compiler and standard library need no metadata at all.
